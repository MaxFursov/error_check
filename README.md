# error_check — бот перевірки товарів «Ділова Ковбаса»

Раз на 2 дні (`CHECK_EVERY_DAYS`) завантажує експорт Проми (`prom_export.xlsx`), шукає помилки в назвах, цінах і даних товарів
та надсилає звіт у Telegram. Про кожну помилку повідомляє **один раз**: наступні звіти містять лише нові.
Якщо помилку виправили, а вона повернулась — повідомить знову.

## Що перевіряється

| Перевірка | Приклад з реального каталогу |
|---|---|
| Змішані кирилиця/латиниця в одному слові | `Cир` (латинська C), `Synnоve` (кирилична о) — на око непомітно, пошук не знайде |
| Вік/тип продукту замість виробника | `Сир … 48% YOUNG` — «Young» це вік сиру, а не ТМ |
| Орфографія та безглузді слова (Claude) | `Camambert`, `Casteiio`, `Нововот роя` |
| Зламані лапки та дужки | `'Баликова"`, `"EDAM 130 г/шт` |
| Занадто коротка назва | `мас`, `шт` |
| *Виведені позиції не перевіряються* | позначені `_ВИВЕДЕНО…` / `Я!ВИВЕДЕНО…` або групою `Я!…` |
| Немає ціни (особливо якщо товар у наявності) | |
| Дублі кодів і назв | |
| Підозріла ціна за кг (ймовірно, ціна пачки) | `Чорізо нарізка 70 г/шт` — 79.96 грн/кг |
| Різка зміна ціни порівняно з минулим запуском | ±40% |
| Архівний товар «в наявності», відсоток > 100 | |
| Дрібниці (лише лічильник і CSV): зайві пробіли, склеєні слова, немає фото | |

Правила працюють без API. Claude (`ai_check.py`) підключається, якщо задано `ANTHROPIC_API_KEY`,
і перевіряє **лише нові або змінені назви** — перший запуск ~2500 назв, далі лише нові.
**Витрати обмежені**: бот рахує реальні токени з відповідей API і не перевищує `AI_MONTHLY_BUDGET_USD` (за замовчуванням $1/місяць) — зупиняється перед порцією, яка б перевищила ліміт, і дочекає наступного запуску/місяця. У кожному звіті є рядок про витрати.
Контекст компанії та список «що не є помилкою» — у `company_context.txt`: додавайте туди нові випадки.

## Чернетки описів

У файлі Проми колонка «Опис» лише дублює назву; справжні описи лежать в «Опис_h2_uk» (HTML: заголовок, склад,
поживна цінність, умови зберігання), заповнено їх лише для ~3% товарів. Бот готує чернетки для решти,
**нічого не змінюючи в Промі** (експорт перезаписується з 1С): результат — окремий `descriptions_YYYY-MM-DD.xlsx` у Telegram.

- Claude бачить лише назву, групу й вагу, тож пише **заголовок у стилі наявних описів + 2–3 нейтральні речення**.
  Склад, калорійність, алергени, ТУ і умови зберігання — дані з етикетки; їх бот **не вигадує**. Для них у файлі
  остання колонка з порожнім шаблоном (у тому ж форматі, що й наявні описи) — заповнюється вручну.
- Відповідь перевіряється кодом: якщо там «склад», «ккал», «ГМО», «натуральний» або числа, яких немає в назві, —
  чернетку відхилено (до 2 спроб на товар).
- Беруться активні товари без опису, спершу в наявності (`DESC_ONLY_IN_STOCK=false` — усі). Раз на `DESC_EVERY_DAYS` (3) дні по `DESC_PER_RUN` (50) за запуск.
- Чернетки зберігаються в `descriptions.json` поруч зі `STATE_PATH` (потрібен Volume). Файл, який не дійшов у Telegram,
  надішлеться наступного разу; товар, якому вже внесли опис у Пром, випадає сам.
- Окремий бюджет `DESC_MONTHLY_BUDGET_USD` (за замовчуванням $3), вимкнено, доки `DESC_ENABLED=true`.

**Без API-ключа (з сесії Claude Code).** Описи може писати сама сесія Claude, а код лише готує запит і перевіряє відповідь:

```bash
python main.py --descriptions-prepare request.txt      # запит: інструкції, зразки, наступні товари (--codes 1,2,3 — конкретні)
# сесія Claude читає request.txt і пише reply.txt: рядки «код | ЗАГОЛОВОК | текст»
python main.py --descriptions-ingest reply.txt         # перевірка тим самим кодом, descriptions.json, reports/descriptions_<дата>.xlsx
```

Telegram за цього режиму необов'язковий: без нього xlsx лишається в `reports/`, і сесія віддає його користувачу сама.

```bash
python main.py --descriptions --dry-run --limit 10   # покаже зразки й запише reports/descriptions_preview.xlsx
python main.py --descriptions                        # згенерувати й надіслати у Telegram
```

## Запуск локально

```bash
pip install -r requirements-dev.txt
cp .env.example .env            # заповнити
python main.py --dry-run        # показати звіт, нічого не надсилати і не зберігати
python main.py --dry-run --file prom_export.xlsx
python main.py --once           # одна перевірка з надсиланням у Telegram
pytest
```

## Деплой на Railway

1. Новий проєкт з цього репозиторію (збирається по `Dockerfile`).
2. Змінні середовища — як у `.env.example` (мінімум `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `ANTHROPIC_API_KEY`).
3. **Додайте Volume** (напр. на `/data`) і задайте `STATE_PATH=/data/state.json`. Без нього після кожного
   перезапуску бот забуде, про що вже повідомляв, і надішле всі помилки заново.
4. Розклад: перевірка раз на 2 дні о 8:00 за Києвом (`SCHEDULE_HOURS`, `CHECK_EVERY_DAYS`). Дата останньої перевірки зберігається у стані, тож перезапуски не викликають зайвих звітів. При старті бот перевіряє, чи пора (`RUN_ON_START=false` — вимкнути).

## Примітка про формат файлу

У файлі Проми `xl/SharedStrings.xml` написано з великої літери. Excel у Windows цього не помічає,
а на Linux `openpyxl` падає з `KeyError`. `loader.py` перепаковує архів перед читанням (є тест).
Якщо Пром змінить колонки — бот надішле в Telegram алерт про зміну формату.
